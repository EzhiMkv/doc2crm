# doc2crm

> Агент «пришёл документ — появилась сделка»: фото счёта в Telegram →
> оформленная сделка в Битрикс24. Извлечение полей, поиск контрагента,
> подбор товаров из каталога, подтверждение человеком.

архитектура — [ARCHITECTURE.md](ARCHITECTURE.md).

## Что это

Уровень production-minded: production-minded MVP на актуальном AI-стеке 2026:

- **Агент на LangGraph** — граф состояний с checkpointing и human-in-the-loop
- **MCP-сервер для Битрикс24** (`bitrix-mcp`) — отдельный open-source пакет
- **RAG**: по загруженным документам (с цитатами) и по товарному каталогу
  (семантический поиск, pgvector, гибридный поиск)
- **Провайдер-агностик LLM-слой**: DeepSeek / GigaChat / YandexGPT /
  self-hosted vLLM + Qwen через OpenAI-совместимый API — под требования 152-ФЗ
- **Метрики вместо обещаний**: точность извлечения по полям, recall@10,
  стоимость одного документа — в этом README

## Сценарии

1. 📄 → 💼 Фото/PDF счёта или акта → сделка в Битриксе с контрагентом,
   товарами и отчётом в таймлайне. Спорные поля — через подтверждение в чате.
2. 🔎 Вопросы по загруженным документам с цитатами источников.
3. 🛒 «Клиенту нужен насос для скважины 30 метров до 30к» — подбор товаров
   из каталога Битрикса семантическим поиском.

## Стек

Python 3.12 · FastAPI · LangGraph · Pydantic v2 · aiogram ·
Postgres + pgvector · Docker Compose · Prometheus · MCP

## Запуск

Появится в ближайшие дни. Потребуются: URL входящего вебхука Битрикс24,
API-ключ LLM-провайдера, токен Telegram-бота.

---

*Проект собирается в паре с AI-агентом (ZCode): код пишет агент, автор
проектирует, ревьюит и умеет объяснить каждое решение. Так теперь вообще
пишут софт — и этот репозиторий, среди прочего, демонстрирует такой workflow.*
